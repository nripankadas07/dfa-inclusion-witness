# dfa-inclusion-witness

Explore the finite DFA product to prove left-language inclusion or return a shortest token counterexample with both state traces.

For parser/protocol engineers checking that an explicit finite recognizer change preserves accepted token sequences.

## Quickstart

Linux/Python3.10+; public source installation, no external service or runtime dependencies.

```sh
git clone https://github.com/nripankadas07/dfa-inclusion-witness.git
cd dfa-inclusion-witness
python -m venv .venv
. .venv/bin/activate
python -m pip install .
dfa-inclusion-witness example.json
```

The command prints deterministic JSON. Invented example returns tokens[a,b]; left accepts while right enters its implicit rejecting sink.

All input examples are invented. The tool reads one UTF-8 JSON file, at most1MiB, rejects duplicate keys/nonfinite numbers/unknown fields and never modifies the input. Exit0 means a completed nonfinding result; exit1 means a documented finding (infeasible deadline, unexpected deadlock, no route or failed inclusion). SQL reports all row outcomes with exit0. Exit2 means malformed/unsupported input with stderr and no partial report. Petri exit3 means incomplete exploration with no deadlock found; a found deadlock uses exit1 even if exploration is incomplete.

## Input and interpretation

Start with the exact structure in [example.json](example.json). [Expected JSON](example-output.json) is generated by the validated example.

Explicit deterministic finite automata only; at most100 states and5000 transitions per machine and32 alphabet tokens. Tokens are nonempty named symbols, not characters to concatenate; the empty-word witness is[]. Missing transitions go to an implicit absorbing rejecting sink represented by null. No regex parser, epsilon/NFA, pushdown/Büchi automata, minimization or equivalence claim from one-way inclusion. Reverse the inputs for the other direction. Sorted tokens resolve shortest-witness ties. At most10201 reachable product pairs.

Identifiers are nonempty strings up to80 characters. Integer bounds exclude booleans. Required keys and types are validated. These are model diagnostics, not automatic changes to a live system. The report describes supplied data only.

## Why this small tool

A failing inclusion comparison needs a small reproducible sequence and both state traces; a finite test corpus cannot establish language inclusion.
